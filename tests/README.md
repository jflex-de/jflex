# JFlex tests

The Maven modules in this directory are end-to-end tests for JFlex that are not deployed.

- `framework`: test support that the test modules depend on: `@TestSpec`, `JFlexTest`,
  `JFlexTestExtension` and the golden tests, the runner of the `.test` cases
  (`AbstractTestsuiteTest`, `TestLoader.flex`), and javac and scanner helpers.
- `generators`: generators that read the Unicode Character Database (UCD): of the Unicode
  tables in `jflex/src/main/java/jflex/core/unicode`, of the Unicode tests, and of the Unicode
  `.test` cases, with the UCD parsers they share.
- `regression`: hand-written end-to-end regression tests, as JUnit tests in
  `src/test/java/de/jflex/testcase` and as `.test` cases in `src/test/cases`.
- `unicode`: tests against the UCD, which this module downloads: the `unicode_x_y` tests for Unicode
  properties, the corresponding `.test` cases, and the tests of the generators that read the UCD.
  The downloads end up in `target/ucd` and in the cache in `~/.m2/`. See
  [docs/howto](../docs/howto/new_unicode_version.md) for how to add a Unicode version.

All modules use `jflex-maven-plugin` from the same build, so install that first and use
`install`, not `test`:

    scripts/mvn-install-fastbuild.sh jflex-maven-plugin
    scripts/test-regression.sh    # ./mvnw -pl tests/framework,tests/regression install
    scripts/test-unicode.sh       # ./mvnw -pl tests/framework,tests/generators,tests/unicode install

CI runs these two scripts as separate jobs. To run a single test, add for instance

    -Dtest=ActionPipeEofTest -Dsurefire.failIfNoSpecifiedTests=false

The tests of `regression` and `unicode` run with `target/work` as their working directory,
which is deleted and filled with a fresh copy of the test data (specs, inputs, goldens) on each
build, in the layout of the module. The purpose is to keep files generated by tests out of the
source tree. This means the tests should be run through Maven; running them from an IDE skips
the copy step.

## The `.test` cases

`TestsuiteTest` in `regression` and `unicode` runs the `.test` cases of its module.
`TestLoader.flex` in `framework` defines their format.

- `src/test/cases/<dir>/<name>.test`: one test case. It names the spec `<name>.flex`, the JFlex
  options, and the scanner's input.
- `<name>-flex.output`: the expected JFlex messages. Paths in it are relative to the module
  directory.
- `<name>.output`, or `<name>-*.input` and `<name>-*.output`: the scanner's input and
  expected output.
- `src/test/resources` (`unicode`): Java code shared by the specs. The shared input files with
  all code points are generated into `target/generated-testsuite/src/test/resources`.
- `src/test/uax/<dir>/` (`unicode`): the specs and `.test` files of the hand-written
  implementations of the UAX #14 and UAX #29 segmentation rules, one per Unicode version.
  Their inputs are the `*BreakTest.txt` files of the UCD, and the goldens are the expected
  breaks in those files.

Add `-Dtestcases=dot,testloader` to run only some case directories.

### Generated Unicode test cases

The `.test` cases for Unicode properties (general category, scripts, line break, ...) are not
checked in. `de.jflex.testsuite.generator.UnicodeCasesGenerator` in `generators` generates them
from the UCD for every version in `de.jflex.ucd.UcdReleases` when the `unicode` module builds.
They are saved into `tests/unicode/target/generated-testsuite`, which has the same layout as the
module. The UAX cases are assembled there from `src/test/uax` and the UCD.

The test case generation is separate from the JFlex implementation.
